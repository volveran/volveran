Volverán

Dead letters come back.

Open-source, self-hosted triage for RabbitMQ dead-letter queues. Hold the messages still, decide what happens to each one, and apply it all in one step.

Looking at a dead letter can cost you the letter

The management UI can peek at a queue, purge all of it, or shovel all of it somewhere else. Every peek requeues the message, and on a quorum queue a requeue can use up one of its delivery attempts.

Real dead-letter work is different: delete these 12, send these 40 back where they came from, move these 3 to a manual-handling queue, and keep a record of who did what.

How it works

  1. Checkout. Volverán holds the messages at the head of the queue, unacknowledged. If Volverán or your browser dies, the broker returns every one.
  2. Decide. Give each message a Decision: Discard, Replay, Move or Keep. A message that failed again after you sent it out is flagged as Died Again.
  3. Apply. Everything is carried out in one step, and you see the outcome for every message. A failure can create a duplicate, but never loses a message.
  4. Audit and Restore. Every action is recorded with who did it. Discarded messages can be brought back.

Don't cause the second incident

The consumer has often only just recovered when the Replay starts. Set a Replay Rate, send one Canary first and watch whether it dies again, and stop part way if it does. Replay rules handle the routine cases on a schedule, and pause themselves when their Replays keep dying.

Know before anyone asks

A dead-letter queue usually gets noticed when someone complains. Volverán keeps watch between visits, without taking a Checkout or reading a message.

  • Depth history for every dead-letter queue, kept 14 days, with marks for each Apply that took messages out.
  • Alerts to Slack, Microsoft Teams or a signed webhook when a queue grows, messages arrive, a Replay rule pauses or a queue starts losing messages.
  • Prometheus metrics on a port of their own, with a ServiceMonitor in the Helm chart.
  • The Dead-letter Map shows where each queue's messages go when they die, and where they are lost for good.

Built for teams

  • Single sign-on through any OIDC provider, with Roles per Broker Profile.
  • Protected Profiles frame production in red and ask for the queue name before anything changes.
  • Four-eyes Approval makes a second Operator confirm a change on a Protected Profile.
  • Signed releases: a cosign-signed image and Helm chart, with an SBOM and provenance.
  • Tested against a real broker: every RabbitMQ behaviour Volverán relies on has a test, run weekly against the latest RabbitMQ 4.

Try it on your laptop

Write profiles.yaml from the example, then open http://127.0.0.1:8080. It listens on loopback only, with no sign-in. On Docker Desktop (macOS, Windows), first turn on host networking in Settings, Resources, Network (version 4.34 or later).

export VOLVERAN_DEV_PASSWORD=guest
docker run --rm --read-only --network host \
  -v "$PWD/profiles.yaml:/config/profiles.yaml:ro" \
  -v volveran-data:/data \
  -e VOLVERAN_OPERATOR="$USER" \
  -e VOLVERAN_DEV_PASSWORD \
  ghcr.io/volveran/volveran:0.6.1

For a shared service, read the Team Mode and Kubernetes guides.
